# 配置 Codex 数学研究

通过符号链接安装时先解析本 SKILL.md 的真实路径；tools/、runtime/、vendor/ 位于实际 skills/ 的上一级。先读 [项目配置](../run-math/references/project-state.md) 和 [轮次合同](../shared/ROUND-WORKFLOW.md)。本版面向具有 create_thread、list_projects、list_threads、read_thread、send_message_to_thread、wait_threads 和 heartbeat 能力的 Codex 桌面宿主。能力不可用时报告实际缺项，不用原生子 Agent 或普通 ChatGPT 对话替代三个独立任务。

用户调用本 setup，即授权按以下确认的配置自动创建三个持久 Codex 任务；不是授权开始数学推理。三个任务平级，Main 统一维护共同事实状态，独立 Sol/medium 原生子 Agent 仍按原合同审核。

## 1. 读取已有配置

配置使用 `.codex/math-sessions.json`，schema 为 `run-math/v1`。已有配置先按 threadId + hostId 读取任务，并结合创建回执及 list_threads 的任务类型、项目上下文核对三个不同任务均为 Codex、属于指定项目目录且不是 Main；已核验配置直接复用，不重新设置模型或推理强度。标题仅作显示，不作为身份。不因任务繁忙或一次读取失败创建替代任务，先核对在途状态。失效绑定报告具体项，用户决定替换后只修复该项。

只处理用户要求的维护区块，其余配置保留。没有有效配置时按首次 setup 处理，不从其他文件推断任务身份。已有事实工作区按下面恢复，不重新初始化数学档案。

## 2. 直接询问模型与推理强度

首次创建前在对话正文询问：“三个证明 session 使用哪个模型和推理强度？创建后你可以在各任务中自行修改，后续 setup 和 run 不会自动重新对齐。”

只列宿主实际支持的模型和组合；可在明确知道 Main 当前配置时作为建议，但仍由用户选择。不把省略 model 当作继承 Main，不凭空推断 Main 型号。用户未明确强度时继续确认其选择；不静默降级。三个 session 初始采用同一组用户选择，创建时显式传 model 和 thinking。保存的是创建时快照，不是需要持续强制执行的配置。以后 send_message_to_thread 省略 model/thinking，保留用户对单个任务的修改。已创建任务不因重跑 setup 自动重配。

## 3. 确认分工、预算及自动接纳策略

复用已有明确决定；首次向用户说明 Main 负责目标与首轮路线 grilling、规划、派发、归档、验收和局部修订；三个持久 Codex session 主推理；另由 Sol/medium 原生子 Agent 独立审核。研究轮预算推荐 3，可选 1、3、5 或自定义正整数，用户明确选择后保存。等待、审核和文章收尾不另计研究轮。

询问本项目采用按轮自动数学 Commit 还是手动接纳，推荐自动；保存本项目用户真实授权原文和来源。已有真实授权直接复用。本套装作者的设计授权不能代替接收者的项目授权；数学 Commit 不是 Git commit/push。自定义分工不能取消独立审核、预算与数学接纳边界。

## 4. 自动创建与可靠绑定

调用 list_projects，按当前项目的真实路径、hostId 选择已保存项目；多项无法判定时在正文澄清，不猜项目 ID。用户调用此 setup 选择在当前项目直接创建三个任务，使用 `target: {type: "project", projectId, environment: {type: "local"}}`，即使是 Git 项也不建立 worktree。不自动增加其他工程、共享目录或远程主机。

创建前把项目、模型、强度、三个 slot 及唯一可读标题写入 `.codex/math-sessions.setup.json` 的恢复记录。逐项先登记 creating，再调用 create_thread，传明确 model、thinking、title 和下方待命 prompt。每个成功返回立即保存真实 threadId、hostId 和原始回执，然后结合创建请求和回执、list_threads 的 kind/项目元数据，以及 read_thread 的可达性与初始化内容核验身份；不得把 clientThreadId 用于 read/send/wait。

创建提示仅用于注册，不消耗研究轮：

> 你是本项目的数学证明 session，等待 Main 后续发送含 task ID 和完整上下文的研究任务。本条仅注册，请简短确认待命，不自行开展研究。你可以读取后续明确授权的研究材料，使用工具做数学验证；仅在 Main 指定的本任务独立产物目录写入实验文件。不得修改共享事实文章、配置、研究状态、他人文件或 Git 状态；不得提交、推送、发布或自行创建任务/后代 Agent。返回候选证明、完整条件、缺口与验证证据；没有数学接纳权，不能把自己或其他 session 的候选当作已证明前提。以后只接受 Main 明确派发的工作，完成后等待。

恢复时复用已成功 ID，只继续尚未创建的 slot。creating 无明确回执或出现 clientThreadId 时先用 list_threads/read_thread 核对创建结果，结合保存的项目、唯一标题、目录和初始化内容核验；标题匹配本身不足以绑定。未能唯一确认时保留待核对状态，报告阻塞，不重试不确定创建、不归档或删除用户任务。list_threads 不是全量可分页检索，查不到不证明创建失败。明确失败且无创建副作用的 slot 才能重试。

read_thread 的公共接口不保证返回 kind/project/cwd，不把缺失字段自行补成已核验。使用真实创建回执与可取得的列表元数据互证；若证据不足以确认任务类型、项目或排除 Main，保留待核对状态，不写正式绑定。

三个真实不同 ID 都核验通过后，展示摘要并原子写入正式配置（同目录临时文件 + 替换），重新读取核对；在此之前恢复记录不算可运行配置。保留必要回执，写入成功后将恢复记录标为 completed。创建时保存 Main 的真实 ID（宿主能提供时）用于自绑定排除，不编造 ID。

## 5. 完成与维护

展示三个任务的真实标题、项目、创建时模型/强度快照、分工、预算及接纳策略；说明当前模型可能已被用户调整，查询工具不能核验时不把快照称为现值。用户改模型可在对应任务中自行完成，不需重新绑定。

随后进入下方材料选择；只完成 setup 时停止，不派发研究、不创建研究 heartbeat。run-math 首次仍需真实 grilling 商定目标与首轮路线。工具受限时报告具体缺项，保留配置和可恢复进度；不伪称三个任务已准备好。

## 6. 初始化或恢复事实工作区

factsRoot 使用已保存配置，默认项目 facts/。尚无工作区时，在读取本地研究正文进行汇编、冻结来源或调用 initializing 前，先在对话正文中问：“是否需要根据这个项目里的本地文件初始化研究？”配置完成、预算选择、目录里存在材料，都不代表同意导入。用户已明确给出本次材料选择时直接复用，不重复询问。

- 用户选择使用本地材料：核对候选文件，说明拟纳入的材料及其数学范围；只使用用户选定的范围。有计算、旧课题或其他不确定材料时先澄清，不能默认整目录均为基线。然后调用 [initializing](../initializing/SKILL.md)，复用准确文章与有效审核，必要时汇编所选材料并审核。
- 用户选择不使用或暂不初始化：只完成对话、分工和预算配置，不创建事实文章、地图或审核任务。将材料选择及真实用户来源记入现有 setup 记录或项目上下文；不另加配置字段。之后由 run-math 先 grilling 明确目标、约定、可用来源和首轮路线，再交回 setup 的初始化分支建立研究起点。
- 从 run-math 返回且上述讨论已经完成：复用材料选择和共同理解，不再次询问是否导入已拒绝的本地材料。按确认的来源调用 initializing；无已有成果时建立仅含目标、定义、约定和开放边界的起始文章并审核，不导入未授权的历史材料、不补造证明。这是建立新研究基线，不是空模板直接开跑。

已有 workspace.json 时只核对状态与版本，不重新初始化、不覆盖历史档案。已有 pending 先恢复文章维护和文章发布；地图来源版本落后只标记待办，文章发布且事实索引同步后可开新轮。旧 runtime 需要升级时先检查兼容性并备份脚本与合同，在 .workflow/lock 下更新。兼容性修复可在证明 session 等待期间进行，不改变派发或数学状态；改变状态结构或含义的迁移等本地事务结束后处理。不改写冻结数学档案。

仅配置分支的完成条件是配置有效、用户材料选择已记录，并说明基线未建立；不以缺少 workspace 为由循环要求初始化。初始化/恢复分支则需事实工作区 status 可读，文章与地图来源版本、路径及哈希有效，文章已发布。初始化地图若尚未独立审核，保留 not-run 原状并明确报告，不伪称通过。材料或授权不足时保留已完成配置，说明缺项，不派发 Codex 推理来偷偷补齐初始化。用户仅要求 setup 时完成后停止；由 run-math 转入则返回原调用方继续其启动讨论或已商定的研究。用户明确要求 setup 后继续研究时可调用 run-math，但不能跳过尚未完成的目标与首轮路线 grilling；单独 setup 不是研究派发授权。

## 探索模式

本版支持在用户确认范围内自动选题、严守轮次预算，并允许无新定理但有依据的认识变化。setup 保留这些协作偏好；run-math 按具体请求选择 proof/explore，不要求用户为探索虚构根命题。已有确认直接复用。视图配置可保存 mapReaderRoot，指向已有 CMath-math-map 项目；查找阅读器时验证真实 server.js、页面和 graph:view 命令。

执行分工与轮次按 [轮次合同](../shared/ROUND-WORKFLOW.md)：Main 规划、路由、验收并优先局部修订；Codex 证明 session 主推理；Sol/medium 独立审核。Main/Sol 后处理不增加推理轮；pending 数学缺口可走关联修订通道。
