# 理解研究结果

通过符号链接安装时，先解析本 SKILL.md 的真实路径。Main 在当前对话执行本技能，交互使用实际安装的 grilling；theorem 与 connect-concepts 按理解重点调用。

## 两种入口与范围

- 研究入口自动交接：一次授权运行的全部轮次结束后调用。接收原目标及真实调整、本次运行标识与轮次范围、轮初基线、最终文章与接纳收据、总结及未完成事项。run-math 按整次运行交接，advancing 独立任务在收尾交接；manual 候选说明未接纳。先完成已授权接纳与文章发布；地图尚未生成不影响进入理解环节，不自动创建地图待办。无新增结果也进入。
- 单独触发：用户调用 `$understand-research`，或要求理解已有研究、解释上次几轮所得、继续先前讲解时使用。不要求先启动或重新运行 run-math。优先依据明确指定的批次、文章或已有理解记录；未指定时从当前对话与工作区定位，只有多个可能范围且无法确定时才用 grilling 澄清，不擅自选最新批次。已有具体问题时直接围绕该问题开始，无需重复选择重点。

两种入口共用以下流程。独立调用不要求存在 run-math 状态或接纳收据：若只给研究文章，核实它实际具有的来源与审核状态，不能把缺少收据的内容称为项目已接纳结果。无法查到原研究目标时明确缺失，再询问用户此次希望理解什么，不倒推出虚构历史目标。恢复已有理解会话时先读记录，仅简要衔接原目标和已讲内容。


## 先回顾原目标，再选择重点

读取本次运行开始时的用户请求、真实 grilling 决定、研究模式与轮初基线；原目标不能用最后一轮的问题倒推或替换。运行中用户改变目标时，分别说明初始目标、确认的调整及其来源。

核对最终事实文章和真实接纳收据、各轮总结与必要原始证据。旧总结可能被后来修正，以最终接纳状态为准。先在对话正文简短说明：

- 推理之前希望解决或理解什么。
- 本次实际尝试了什么，哪些路线奏效或没有推进。
- 得到了什么：区分原有事实、本次新增结果、文献输入、候选与开放问题。
- 这些结果怎样回应原目标，仍缺什么。

随后实际读取并遵循环境中的 grilling/SKILL.md，不仅模仿其格式。没有专用 Skill 工具时按当前环境读取并执行；缺少技能时说明缺失，不能声称已经调用。以用户的理解重点构建设计树，将当前前提已确定的问题作为本轮 frontier，一起在正文编号提出，每题给建议；等待用户回答后更新下一轮。推荐一个与原目标相关的切入点，让用户决定先深入哪里，不先铺开整篇证明。用户已明确的偏好直接沿用。

## 在对话正文中讲解

先回应用户当前疑问，再提出由此产生且确需用户选择的问题。提问用于确定疑惑与讲解重点；必要时可用小例子或推理问题帮助核对理解，不默认要求复述证明、考试或评分。未知事实由 Main 按 grilling 规则调查，不向用户索取可查事实。

按选定问题实际读取并使用 theorem 或 connect-concepts，无需每次两者都用，也不固定先后顺序：

- theorem：完整说明对象、量词、假设、定义与结论，解释关键证明机制及各条件用途。逐步证明按用户反馈深入。
- connect-concepts：说明结果与原目标、其他结果的关系，区分条件性蕴含、方法、类比及尚未接通的部分；每个推导写出必要附加条件和当前项目是否满足。

本调用范围优先采用正文交互讲解，不采用两个技能默认的长篇模板、自动多文件输出或历史拓展。讲解和数学公式直接输出在对话正文，不默认生成详细 Markdown、HTML、PDF 或只交付文件链接。用户要求详细笔记时才另生成。不得虚构假设必要性的反例、文献首创性或缺失的数学桥梁。

目标是帮助用户把握主要结果的准确条件、结论及其对原目标的贡献。用户的疑问与回答决定展开顺序；不要把解释选择问答当作理解证明。

## 结束、暂停与异常

待解释分支讲清后，由用户确认“理解了”结束；“先到这里”表示暂停，保留未展开问题，不声称已全部理解。用户未回复时保持待续，不视为确认，不用 heartbeat 反复催问。grilling 中需要确认的是理解或新决定，不是逐段解释许可。

无新增结果时，重点解释调查所得、失败原因或尚不明确的原因、排除范围和剩余限制，不制造新定理。运行中断时先说明已归档部分、未回收任务与未完成边界，再询问先理解现状还是恢复研究；只在用户选择后执行依赖该选择的工作。用户明确停止交流时只保存状态，不继续提问。

讲解不增加研究轮、Attempt、Commit 或审核层，不自动恢复 Codex session 派发或延长预算。发现讲解遗漏直接修订解释；发现可能的数学缺口则明确报告并按既有研究更正接口处理，未经审核不能改成已接纳事实。用户认同或理解测试不替代数学审核。

## 理解成果与下游选择

共同梳理主要结果、完整条件、关键中间引理和直接证明关系，使用户理解与证明表达一起变清晰。仅讲解展开直接修订正文解释；需写回事实文章时，纯编辑走 maintain-math-article 的编辑接口，新增论证或数学修改走增量审核和 Commit，再返回当前理解会话，不递归开启教学。

用户确认梳理完成后，以 grilling 让用户选择整理数学地图或暂不继续；也可明确选择继续到 Lean 蓝图或形式化。已有明确选择直接沿用。“先到这里”只暂停。继续时先调用 to-map，再由轻量独立 map-review 核对并发布；已有匹配文章版本且审核适用的地图直接复用。用户要求蓝图或形式化时，在地图之后调用 [formalize-research](../formalize-research/SKILL.md)，交接选定范围、准确文章版本、理解记录与已核对地图。局部形式化只需目标及必要依赖的局部地图。只选建图不自动进入蓝图，只选蓝图不自动推进整项证明。文章是数学内容依据，地图保存数学结构，Lean 蓝图在此基础上补充形式化对应与任务；旧图保留来源版本。

## 一份轻量理解记录

在项目 `research/teaching/<run-id>/understanding.md` 维护一份简短记录，run-id 使用本次真实运行标识；独立理解没有运行标识时，使用描述本次材料的主题与日期作为记录目录名，不伪造研究运行。若同一标识已有旧记录，保留旧内容并按实际调用的时间和轮次范围分段，不能覆盖另一批次。记录原目标及来源、实际轮次范围、最终文章与接纳收据位置、关键解释、用户明确反馈、待解释分支、结束/暂停/待续状态和下次继续位置；可引用真实对话，不默认复制全文或新增多份产物。

理解记录不是数学事实权威，也不改写已冻结的轮次总结或已完成的教学文件。恢复时先读记录与当前材料，只接续未完成的理解问题。仅完成材料核对或开场不能登记为“用户已理解”。
