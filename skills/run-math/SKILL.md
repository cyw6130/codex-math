# Codex 数学研究

本地 Main 负责证明规划、选题、路由、归档、验收和首轮增量修订（含短证明补齐）；三个独立 Codex session 承担主要推理，独立 Sol 子 Agent 承担审核与定向复核。run-math 与 advancing 是平行研究入口，不调用 advancing skill；本流程直接使用共享 article_flow 的 start/finish 保存档案。先读 [项目配置](references/project-state.md) 和 [轮次合同](../shared/ROUND-WORKFLOW.md)。

## 1. 确认研究意图与模式

从用户真实请求识别 `proof` 或 `explore`，记录原文与来源引用。要求证明明确命题时用 proof；希望理解对象、发现自然问题、发展理论时用 explore。模式可以直接识别，但不等于目标与首轮路线已经商定。首次进入一项研究（包括 setup 后第一次 run-math），先按 [研究讨论](../shared/ROUND-WORKFLOW.md#main-与用户的研究讨论) 实际调用 grilling：与用户明确精确目标/研究意向、关键约定与可用来源，解释候选路线和困难，商定首轮主要方向及要解决的问题。用户只给入口时从对象和兴趣谈起，不要求预先提供猜想；只有猜想名称或旧文章里的根目标也不能代替此次路线讨论。

提出当前可问的问题并等待真实回答，共同理解确认后才进入轮初冻结和派发。不能把读取 grilling 文件、单向宣布路线、已有预算或自行写一份 grilling 记录当成完成讨论；也不能先派发再补问。若已有真实对话明确商定了同一目标与首轮路线，简短回顾并复用，不再重复问。尚无可信证明路线时，可以共同决定首轮调查路线或检查可行性，不假装已有证明方案。具体子任务拆分仍由 Main 完成。

- proof：读 [证明路由](references/proof-routing.md)，固定根命题与真值相关约定；沿用 proof-state/v1。
- explore：读 [探索路由](references/exploration-routing.md)，固定研究对象、兴趣、范围、约定与选题权限；每轮具体问题可以变化，不创建虚构根命题。

首轮路线商定后，预算内后续推理轮允许 Main 在同一目标和约定下大幅调整方法、分支与任务分配，简短说明依据即可，不等待逐轮批准。改变研究对象/兴趣边界、根命题、影响结论的额外假设或主要产物方向时，重新 grilling 取得用户明确决定；已有真实明确决定可以复用。继续研究预算默认来自 setup，单次明确预算优先；不因探索没有终点而自动延长。用户说“继续”且已有共识仍适用时直接续跑；恢复在途任务或本地收尾不重做启动讨论，不重发任务。

按 [研究讨论](../shared/ROUND-WORKFLOW.md#main-与用户的研究讨论) 主动调用 grilling，与用户探讨研究意图、新发现的意义及更自然的问题。任务明确时也可有依据地挑战原目标；等待仅暂停依赖用户回答的工作，已授权的独立工作继续。

## 2. 核对配置与既有材料

读取 .codex/math-sessions.json，按项目配置核对三个独立 Codex session。用 read_thread 确认每个已绑定任务与现场；没有有效配置则交 setup-math。不要用普通 ChatGPT 对话或原生子 Agent 替代。

先查配置、现有研究状态和材料选择；这些只读调查可以为步骤 1 的讨论提供依据。已有工作区则经 status 核对基线和 pending；首次没有 facts/workspace.json 时不直接运行 status，也不因此绕过讨论去汇编本地文件。若 setup 已选择不使用本地材料，先完成目标与首轮路线 grilling，再将已确认目标、来源范围和材料选择交 setup-math 的初始化分支；选择未定时由 setup 询问。run-math 不自行执行初始化，已确认配置保留，基线就绪后再派发。只读恢复现有状态不等于授权导入其他材料。

已有文章 pending 或事实索引未同步先恢复；旧地图保留来源版本，滞后本身不是研究待办，不阻塞下一轮；数学缺口优先由 Main 按文章接口关联修订，确需证明 session 的修复轮可沿该通道派发。从理解完成或地图完成处继续时，复用仍适用的目标与路线共识；旧预算耗尽时确定本次新增轮数，不自动重置。读取授权范围内目标相关的原始材料、已接纳文章、失败记录和来源边界；必要文献调查与命题是否已知由调度者核实。explore 的选题调查借鉴 explore-research：给出材料依据、已有理解、自然缺口和选择理由；首轮兴趣和方向商定后，已授权范围内自动选题，不再每轮请用户批准一次 Advance。

## 3. 准备轮初上下文与决定

首次研究在真实启动讨论完成后才进入本节。将用户目标、首轮路线共识及真实回答来源写入已有 context/研究契约记录；续轮引用仍适用的讨论并说明本轮路线变化，不补造用户批准。grilling 问答轮不计入推理预算，多个 Codex 证明 session 同轮派发仍只计一个推理轮。

轮次严格遵循轮次合同的 v2 定义；每轮使用 `research/results/<target>/round-<N>/dispatch/`，与 round.json 同属一个轮次目录，首次 sending 计入预算，关闭后禁止追加派发。每轮先制作共同 context.md，再在首次派发前运行共享归档脚本 `python3 FLOW ROOT start ATTEMPT_ID`（按文章接口传齐参数），将该文件作为 --source 连同文章、地图、研究契约、模式状态和必要材料冻结；同轮只 start 一次。建立带 SHA-256 的 context.md，完整写出定义、约定、有效前提、开放问题、已排除路线、撤回项及本轮范围。派发正文包含 task ID、上下文哈希和全部必需数学材料，不能只发本地路径或依赖 Codex session 的旧对话记忆。

按选定模式生成状态与 decision，以 `node tools/validate-research.mjs STATE DECISION` 校验后保存不可变决定。proof 任务绑定义务，explore 任务绑定有依据的自然问题和预期理解变化。校验失败不派发，修复数据或通过 grilling 改变原则决定。

## 4. 派发与恢复

读取 [派发合同](references/dispatch-recovery.md)。每项先保存完整 prompt 和 prepared，再记录 sending，之后调用 send_message_to_thread。逐项保存真实回执，不把整个并行波次当一次成功；发送不确定先读取对应任务核对，不盲目重发。

只在共享前提固定、任务相互独立且预计有研究收益时并行。每对话每轮最多一次补充派发；仅用轮初已接纳前提，并在补充 decision 的附带记录写明新增理解收益、可能增加的等待及为何不留到下轮。无明确收益时等待本轮统一整理，不为占满对话池而追加。

## 5. 等待、预算与轮次屏障

每目标只维护一个保存了 ID 的 heartbeat，空检查保持安静。它负责证明 session 长任务和中断恢复；Main 活跃时按派发合同用 wait_threads 有界等待，返回后及时接续。Sol 审核按共享轮次合同用完成通知或有界等待，返回后 Main 立即接续，不等 heartbeat。新派发通常 15 分钟后恢复检查，无结果最多间隔 30 分钟；下一检查还须不晚于所有在途任务最早绝对 deadline。每项从 sending 起最多 120 分钟，补充派发不重置旧任务期限。dispatch_log 的 next-check 提供实际时刻。

回收所有首次及补充任务后才能统一整理。任务到期先做最终读取核对；仍无结果时停止派发、保存 interrupted 档案和 blocked 状态，报告具体未返回任务。恢复前先核对既有发送状态与对话；不跳过在途任务开启新轮次。轮次预算从首次派发计数，检查与收尾不增加研究预算。

## 6. 按轮整理与接纳

读取 [研究产物](references/research-artifacts.md)。完整原文随到随存，每轮只写一份总结：当前理解/命题状态、具体发现、失败与排除、剩余问题、下一步依据。explore 的问题形成和有依据的认识变化进入 exploration.json 并与原文一起冻结；没有新定理的一轮可以有理解进展。重要发现、反例或瓶颈值得共同讨论时，Main 消化材料后按研究讨论规则调用 grilling；不把每次返回都变成问答或提交门槛。

有可审核数学内容才调用 prepare-math-increment，产生一份合并候选增量；先以 dispatch_log close 关闭推理阶段，把 closed.json 连同原始记录传 finish --evidence，round.json 使用 v2 并指定 closure。finish 后由 round_flow 准备自动请求、独立 fact-increment 审核、accept、maintain-math-article 维护完整事实文章、按共享文章合同分级核对整合后 publish-article 并同步事实索引。无数学增量用 no_change 收尾，仍保留总结和探索记录。发现猜想不等于证明：事实总稿可收入准确标注的开放问题与条件性结论。

审核意见先交 Main 判断；误读先澄清，编辑集中处理，需改变数学时再形成修订增量，优先交原 Sol 定向复核。文章整合是否另请 Sol 由 Main 按共享文章接口判断；这些都属于原轮后处理。只有关闭后新派发实质 Codex 研究才增加推理轮，预算耗尽仍可做 Main/Sol 收尾。文章整合核对后立即 publish-article，再同步有效结果索引与模式状态，有预算便可进入下一轮。本运行不调用 to-map 或 map-review，不创建每轮地图待办，也不要求地图更新后才结束。文章未发布的数学问题用 start --repair-of，已发布文章的数学问题登记失效并基于当前文章另存更正增量；均先经独立审核和 Commit。探索记录的 recorded/understanding_advanced 不授予已证明前提身份。

## 7. 收尾与查看

proof 只有根命题完成且全部有效证据可核对，才可设 completed 并自动完整写作。explore 从不因局部命题证明或预算结束宣称理论完成；预算耗尽、无有依据新问题、等待外部输入或用户停止时收尾，完整成文仅按用户要求。

收尾先说明理解到哪里、可靠内容与开放边界，再说明审核/提交/地图状态、预算和下一方向。保留必要恢复信息并在没有在途研究任务及需恢复的文章工作时停止当前 heartbeat；否则保留必要接续并明确尚未完成项。旧地图滞后不维持研究 heartbeat；另行明确启动的地图任务按其自身恢复记录处理。每次运行结束后必须调用独立技能 [understand-research](../understand-research/SKILL.md) 自动交接：先回顾推理前确认的原目标，再概述本次尝试、结果及剩余缺口，实际调用 grilling 选择理解重点，并按需调用 theorem、connect-concepts 在对话正文中讲解。无新增结果和中断按该环节的边界处理；用户要求停止交流时不继续提问。下一阶段的待定选择不阻塞本阶段已授权的收尾。

查看调用 [view-map](../view-map/SKILL.md) 或 [view-trajectory](../view-trajectory/SKILL.md)。查看旧地图须显示其对应文章版本；不因查看或发布增量自动生成地图。实际研究轮次保留真实过程记录；没有匹配地图时如实说明，不伪造新地图轨迹。查看不启动研究，不消耗预算。
