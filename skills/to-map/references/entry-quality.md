# Entry 的含义与提取质量

## 沿用能力包定义

本套装的分类权威是随包保存的 [math-graph-semantics-v3 合同](../../../vendor/math-graph-semantics-v3/contract/MATH_MAP_STATE_SPACE_V3.md)，具体字段和关系见 [格式合同](math-map-format.md)。Entry = Fact | Claim；Fact 包含 definition、algorithm、calculation；Claim 包含 lemma、proposition、theorem。Claim kind 表达当前项目的叙事用途，不表示可信程度或证明状态。

此次核对来源为 CMath-capabilities 的 `packages/math-map/state/math-graph-semantics-v3`；同库 `entry-model-v2/contract/ENTRY_ARCHIVE_V2.md` 也引用此 v3 分类，身份和来源等存档信息不改变数学陈述。旧 `packages/core/cmath-entry-model.mjs` 的 Harness 兼容模型把 calculation 归为 Claim，不能混入本套装。

历史 `mathematical-entry-inference-authoring-v1/manifest.json` 保留了“数学正文保持权威，审查记录不替代 Entry 陈述或 Inference 推导”以及“背景、路线和解释性总结不得仅靠合法枚举成为 Claim 或 proof”的设计决定。该包当前未激活，引用的完整合同未在此次检索位置找到；这里只借鉴已核实的设计说明，不导入其旧版类型或仅面向成熟数学的范围限制。

以下是上述定义的写作与提取指导，不增加类型、字段或机械验收指标。

## 让条目可理解、可引用

- **Definition 明确在定义什么。** 写出对象、符号或一类数据的名称及定义。若定义“满足这些条件的数据”，应有明确的名称和后续用途。仅为某个命题罗列假设，通常留在该命题中；不要为增加节点而另造天然可用的 Fact。
- **Claim 明确适用条件。** 陈述结果、条件与量词；较长的共同背景可引用地图中准确的数据定义，不必每条复制全文。避免仅写“上述条件”“文章实际数据”而无法定位。来源位置负责溯源，不能代替数学条件的表达。
- **按独立引用用途决定粒度。** 不同用途或来源的外部定理通常分开，便于推导准确引用；同一结构定理的紧密相关结论可以合并。判断某条是否有独立定义或引用价值，还是重复已有命题的假设。使用次数也不是门槛：仅用一次的定义仍可能有独立概念或引用价值。没有字数、句数、节点数配额。
- **算法、计算与断言分清。** 描述算法过程或具体计算内容可以是 Fact；算法正确性、一般性存在或唯一性等断言按其用途写成 Claim。不要靠换 kind 绕过证明依赖。
- **Inference 保留真实的直接依赖和论证。** proof 的结论是 Claim；organization 仅表达来源支持的概念形成，结论是 Definition。不能把背景相关、研究路线或章节顺序画成推导。

例如，把数个独立外部工具打包为“代数群输入”，会让每条 proof 看似同时依赖全部工具；宜按实际调用分开。“局部性条件”若只是一个定理的假设，放回定理；若文章确实要定义一类满足这些条件的算子，则给这类算子一个准确的数据定义。引用“G.2 的数据”时，应指到具体定义，并保留本结论额外需要的条件。

## 从文章提取，而非复制段落

先辨认原文提供的定义或结果及其用途，再组织 statement。Claim 先让读者看到完整条件与结论，Inference.argument 保留如何推出它。不要把同一证明段落原样填两处来代替这一步；但不因两处重复、含有短证明或篇幅较长就判失败。准确命名的共享背景可以引用，不要求每个节点复制全部定义。

| 文章中的写法 | 提取时怎样处理 |
|---|---|
| “此时式（10）给出 q=0，故扩张分裂” | 从原文补全扩张对象、范畴和适用条件，陈述哪些扩张必然分裂；该计算进入对应 Inference。 |
| “得到开头的全部等价关系” | 明写原文实际证明的等价链，或收窄条目标题和结论；不能只附来源位置。 |
| “下面定理假设 A、H、w 满足……” | 一次性假设留在命题中；原文确实形成有名称、有用途的数据类时，才提取为 Definition。 |
| “这关闭了某个问题，下一步需要核查……” | 留在文章或研究记录；其中若有独立数学推论，另以准确条件和结论表达。 |

Lemma / Proposition / Theorem 按全项目叙事用途判断，不因原文章节称“定理”或结果位于证明中就批量改类。已接纳角色的调整交 Main 按既有合同处理。

## 在现有审核里区分问题与建议

map-review 对本次范围既核对来源，也阅读 Entry 及其明确引用的共享背景，判断读者能否理解并引用它；前提连线或来源页码不能自动补足含混陈述。对发现的问题指出具体缺少的条件、结论或定义对象，不只重复“与来源一致”。

- **需要修复的提取问题**：遗漏必要条件或结论、标题与内容不符、以未决研究评论充作已证 Claim、Definition 没有明确对象或定义用途。它们影响可理解性、忠实性或正确使用，应进入已有问题记录。
- **可选的表达改善**：条件和结论已经清楚，只是文字较长、解释重复、编排可改进或叙事角色有另一种合理选择。放在现有 summary 或报告正文的建议中；不因此扣分、写成 unresolved 或阻塞发布。不要把真实内容缺陷降为润色以求通过。

这些问题首先在 to-map 提取时处理，map-review 在本次审核范围内独立核对。Main 优先按原文修正表达或提取，再让原独立 reviewer 核对变化及影响；不增加研究轮或新的审核层。若需要补出原文没有的数学条件或论证，交 Main 走文章更正通道，不能由提图者补造。
