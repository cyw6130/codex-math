# 文章到地图

文章整理后，同一数学结果在摘要、主文与附录的重复表述使用同一结果身份和多个来源定位。按实际对象、条件、结论及独立证明关系判断合并；章节移动或新增表述不自动产生新 Entry/Inference。优先保留适用的旧 ID，被合并或删除对象在现有 source-check 中记录去向与依据；不同适用范围和有独立价值的证明、反例仍须保留。不得用目标节点数决定取舍。

先读 [格式合同](references/math-map-format.md) 和 [Entry 含义与提取质量](references/entry-quality.md)。输入为 Commit 后 article.json 绑定的完整事实文章 paper.md，或初始化、已发布纯编辑修订及仅地图维护时由 workspace 指向的准确当前文章；研究轮结束不构成建图授权。由 understand-research 梳理后用户选择建图，或用户单独明确要求建图时执行；沿用明确范围，不重复 grilling。新输入范围有歧义时才澄清。

先读取已有理解记录中的主要结果目录、关键条件与证明结构，核对它们对应的当前文章位置；以此组织提取，不从零重新设计研究路线。理解记录缺失时使用文章总览，不虚构用户已经理解；记录中的新解释、类比或未写回证明不能直接入图。目录不代替全文覆盖，重要旁支仍须保留。

首次提图按章节读取全文；后续从文章变化与受影响部分更新，复用适用的来源记录和旧图稳定 ID，全文始终是内容依据。提取主要定义、结果、计算、外部前提和关键直接证明依赖，保留条件、量词、约定、开放边界与重要旁支。不能从章节顺序补造研究历史或从摘要代替全文提取。开放问题/猜想保留明确标题与正文标识，不因文章已接纳而加入 B0 或虚构 proof；条件性结论完整保留条件。严格 v3 没有独立 epistemicStatus 字段，状态说明放在原有标题/陈述和 source-check 侧录中，不添加非法字段。

先识别原文中可独立引用的数学对象或结论，再写 Entry；不要按段落切块后直接同时填入 statement 和 proof argument。Definition 写清定义的对象或数据类；Claim 写清条件、量词和结论，标题声称的分类或等价关系须在陈述中落实。共享背景引用准确 Entry，不能只留下“此时”“前述”“见正文”。Inference 承担相应推导，研究意义和后续打算留在文章或过程记录中。完整陈述可以较长，短计算也可帮助理解；不按长度、重复率或节点数量决定合格性，具体例子见 Entry 质量指导。

对新增、修改对象回查原文，再从读者角度读一次条目及其准确引用的共享背景，确认无需猜测文章上下文即可理解；从文章变化处反向检查是否漏提，检查条件、符号和依赖受到影响的旧对象。首次提图或缺少可靠提取基础时扩大到全文。source-check.json 绑定当前 source_sha256，保留实际读取范围、对象来源与理由、文章覆盖和未解决问题；用现有理由说明有争议的拆分、合并或不提取选择，不新增逐条写作表单。适用旧记录可引用复用，但需更新移位的来源定位。新增和删除对象均有处置说明。独立审核的复用依据以 map-review 核实的旧审核为准，提取者自查不替代独立审核。

使用本套装 `node tools/validate-map.mjs PAPER MAP VALIDATION_JSON` 运行随包的 deriveMathState；脚本保存实际 source_sha256、map_sha256、validator、errors 和派生状态。路径相对套装根解析。校验失败修复图并重跑，不能补写通过结果。

将 MAP、source-check.json 和 validation.json 交 Main 按文章接口 map-packet --current 及独立 map-review；既有明确地图任务恢复时保留原版本包。审核通过后由 Main 按同一接口 publish 地图，不重新触发文章维护与研究。通过格式校验只代表结构/语义规则通过；独立提取忠实性审核仍需真实完成。来源数学问题先交 Main；需数学更正时按文章接口接续关联 Commit，图修订本身不改文章。

## 交接 Lean 蓝图

数学地图保存文章的对象、结论与证明依赖，轻量独立 map-review 核对后才作为 Lean 蓝图的结构起点。用户已要求蓝图或形式化时，交接 formalize-research，复用稳定 ID 并补充 Lean 声明、Mathlib 对应、缺失引理与证明任务；仅请求建图时到地图发布为止。局部形式化可仅提取目标及其必要依赖，明确局部范围，不声称全文覆盖。
