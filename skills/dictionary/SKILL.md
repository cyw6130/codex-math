# Codex Math 术语查询

解释本套装的系统概念，不建立另一份数学事实或流程规则。通过符号链接安装时先解析本 SKILL.md 的真实路径，按真实路径定位套装来源；不能把用户研究项目中同名的 CONTEXT.md 当作本套装定义。

## 查询流程

1. 用户已有明确术语或关系问题时直接查询。没有问题或有影响答案的歧义时，实际读取并遵循 [grilling](../grilling/SKILL.md)，仅围绕查询对象在正文澄清；最多列三个有依据的候选，不启动研究目标或路线讨论，也不要求用户提供可查事实。
2. 先读 [来源索引](references/source-map.md)，按正式名、别名和问题含义定位本版的相关来源。项目定位看 [CONTEXT.md](../../CONTEXT.md)，术语含义、权限和时序以索引指向的现行共享合同及入口正文为准。索引只保存来源，不复制第二套定义。
3. 默认先给简明解释，再说明一个关键区别和可点击来源；用户问关系、理由或实现状态时才展开。没有定义的词明确说“本版尚未定义”，不从 Skill OS 或其他项目移植 M/R、Kernel、Research Interval 等专有含义。
4. 查询运行行为时分别核对技能规定、实现代码、本地检查和真实宿主运行证据。“写入 SKILL.md”不等于工具已执行，“本地测试通过”不等于三个 session 端到端运行通过；是否进入公开版本应核对当前 Git 版本或真实发行材料。只回答有证据的层次，不强行给出全部状态。
5. 不一致时明确报告“文档与实现不一致”，列出对应来源、版本及证据边界，不静默裁决或自行修复。仓库中的历史验证报告不能当作本次改动已经验证的证明。
6. 查完即返回。不创建或发送任务，不建立 heartbeat，不运行 setup/run、数学计算、审核或 Commit，不改配置、文章、地图、研究日志或 GitHub Issue。读取某项目的实际状态时，只按用户给定或可确定的项目范围做必要只读核对，不初始化缺失状态。

## 本版必须保留的区别

- Main、三个持久 Codex 证明 session、独立原生审核子 Agent：职责与权限不同，session 不是临时审核者。
- 模型与推理强度由 setup 询问；创建时快照不保证是任务现值，后续不自动对齐。
- 研究轮次、检查、审核修订和文章收尾：预算按数学推理首次 sending 计数，不按回复或检查次数计数。
- 候选、Evidence、已审核、已接纳、文章已发布：不是同一个阶段；准确标注的开放问题被收入文章不等于命题已证明。
- 数学 Commit 与 Git commit；本地事实文章发布与对外发布：不能混称。
- proof 与 explore；no_change 与没有理解进展：按各自合同区分。
- 事实文章、派生论文、数学地图、研究轨迹：用途和权威不同，旧地图不自动阻塞新轮。

这些是查问时应核对的区别，具体定义和例外仍读取来源索引中的合同。

## 范围与失败处理

- 系统术语：本技能直接解释。
- 某个已有数学结果或证明步骤：说明可使用 [understand-research](../understand-research/SKILL.md)，不自动调用或补造新证明。
- 如何配置、开始或继续：可指出 [setup-math](../setup-math/SKILL.md)、[run-math](../run-math/SKILL.md) 的适用入口，但不代为执行。
- 来源缺失、过期或冲突：报告缺项和已核实部分，不把未定义补成设计决定。
- 一般数学术语或项目外知识：说明不属于本系统词典；不假称本套装已有定义。

查询不消耗研究预算，不创建 Attempt/Evidence 或新的接纳记录，也不要求查询前已经完成 setup。
