# 结对形式化研究

解析本技能真实路径再读取相对资源。以准确文章为数学内容依据，在当前对话中解释数学与代码。先实际读取环境中的 grilling/SKILL.md，遵循设计树、当前 frontier、建议及等待规则；不只模仿提问格式。用户已明确的目标与选择直接沿用。按需读取 theorem 或 connect-concepts，讲解在正文中，不默认生成长篇教学文件。

## 入口、已有工程与权限

可由用户独立指定文章、定理或已有形式化工程，也可由 understand-research 在用户选择后交接。只请求“准备蓝图”时停在蓝图与陈述草案，不自动执行整项证明。完整形式化授权后在所选范围内推进，但关键数学决定仍按下文共同讨论。run-math 不自动调用本技能；形式化不增加或恢复 Codex 研究轮次。

先检查现有工程、lean-toolchain、lakefile、lake-manifest、构建/审计脚本及已有运行约定。Lean/lake 路径存在不等于目标版本和依赖可用；核对工程固定版本。已有本地或远程检查环境优先复用，不重装、不升级、不覆盖现有代码。用户引用其他任务时先读取任务；引用提供上下文，不自动授权修改该任务工程或重新派发。远程执行前确认当前授权包含对应主机、同步范围和命令，复用隔离快照，不能将本地版本检查当作远程构建成功。无可用环境时说明具体缺项并完成不依赖环境的目标梳理。

## 1. 选择目标

绑定准确文章路径、SHA-256、目标稳定 ID/锚点、所选主定理及必要依赖。核对项目真实接纳收据；外部文章或未接纳材料明确其状态，不虚构接纳。grilling 确定范围和希望重点理解的证明。原目标不可被更弱的 Lean 目标替换。

## 2. 盘点基础与表示

检索当前固定 Mathlib 和本地库，把所需定义、定理区分为直接复用、需适配、缺失。展示核心对象的候选表示与具体例子，共同确定表示方式；只解释当前用到的 Lean 概念。外部结果记录实际声明全名或尚缺证明，不凭名称相似认定可复用。实现时查当前环境/官方文档，不猜测 API。

## 3. 复用结构准备蓝图

已有数学地图作为起点：核对地图的文章版本，选取目标及其相关证明链，回查准确文章，保留稳定结果 ID。地图是 Lean 蓝图的前一步。地图滞后或不存在时，先调用 to-map 从准确文章补齐所选目标的数学地图，再经轻量独立 map-review 核对；只形式化局部结果时，仅整理目标及必要依赖的局部地图，不要求提取全文。已有匹配版本且审核适用的地图直接复用。自然语言数学依赖与 Lean 声明/import/辅助引理依赖分别记录，不把概念相关边当证明依赖。

Lean 蓝图复用已核对地图的稳定对象与证明依赖，补充 Lean 声明、Mathlib 对应、缺失引理和证明任务，不另建一份重复的数学结构。为需要独立实现的步骤补局部辅助引理，建立 Lean 陈述骨架；允许草稿使用 sorry，但明确未完成。形式化专用引理先留在代码侧；新数学结果若需回写文章，走既有增量审核。蓝图只表示待实现计划，不等同通过验证。

## 4. 对齐并独立审核陈述

核心定义、主定理和关键引理并排展示文章陈述、Lean 声明及数学解释，与用户共同核对。对照对象实际定义及其传递引用，检查量词、非空/有限维/域等条件、结论强度、参数和约定；防止把待证性质塞进结构字段、以不可能假设使目标空真，或用同名错误定义换题。

使用未参与本次形式陈述及核心定义翻译的独立 reviewer 对照源码和原文，真实保存审核意见；数学语义审核采用适用模型路由。审查可按相关声明成组，不每个 tactic 派审。用户确认表示理解与意图对齐，不代替独立忠实性审核；Lean 内核也不证明代码表达了论文原意。

## 5. 小步证明

按已讨论依赖推进：讨论下一步数学思路 → 用户尝试或 Main 实现 → 运行实际检查 → 展示对应假设/目标变化 → 解释完成的数学步骤。用户愿意才练习，不强制复述或考试；“直接做”允许批量处理已选路线。常规语法、检索和调试自动完成。

只修改授权文件、证明体与必要辅助内容；目标陈述、核心定义和实质路线变化先 grilling。展示的 Lean 目标须来自真实 InfoView、诊断或运行输出；只有文字推演时标明未运行，不能模拟成功。局部通过不等于整个目标依赖闭合。

## 6. 卡点回流

分别记录陈述问题、数学缺口、库缺失、拆分问题和工具问题及实际失败尝试。重复相同失败且无新依据时停止重试，提出具体替代或交回用户选择。换关键证明路线前说明与原文的区别；另一证明通过不代表原证明逐步核查完成。

允许使用明确列出的外部假设完成阶段性条件证明，优先用命题参数表达。它不改变论文原目标；目标中新增条件与未完成依赖都在记录中显式展示，不偷加公理。数学文章需要改动时，纯编辑走 maintain-math-article，新增论证/条件变更走增量审核与 Commit，再返回本会话。暂不修改已接纳文章以求编译通过。

## 7. 集成、验收与共同复盘

按 [记录与验收](references/verification.md) 对准确代码快照执行完整构建、目标加载、公理与未完成依赖检查；复核最终陈述，重大定义或陈述修改使相关旧语义审核待复核。未运行、失败、部分验证、条件性验证如实区分。核对通过后一起走过主定理关键证明；用户确认自己的理解状态，允许“代码已验证，但仍有疑问”。用户暂停时保存继续位置，不自动追加研究或反复催问。
